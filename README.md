# show-local

**תגידו ל-Claude "תציג לי" והתוצאה נפתחת אצלכם: בדפדפן ברירת המחדל שלכם, בסייר הקבצים או בנגן, ולא בחלון תצוגה בתוך Claude. והוא בודק שזה באמת נפתח לפני שהוא אומר "פתחתי".**

פלאגין ל-Claude Code, גם לאפליקציית הדסקטופ וגם לטרמינל. מתקינים פעם אחת, ומשם זה עובד לבד.

[English README](README.en.md)

## התקנה

בתוך Claude Code:

```
/plugin marketplace add ofeklevy11/show-local
/plugin install show-local@show-local
```

או בשורה אחת מהטרמינל:

```bash
claude plugin marketplace add ofeklevy11/show-local && claude plugin install show-local@show-local
```

<details><summary>סקריפט התקנה (Windows / macOS / Linux)</summary>

```powershell
irm https://raw.githubusercontent.com/ofeklevy11/show-local/main/install.ps1 | iex
```
```bash
curl -fsSL https://raw.githubusercontent.com/ofeklevy11/show-local/main/install.sh | sh
```

אם שלב כלשהו נכשל, הסקריפט אומר איזה שלב ומסתיים בשגיאה (קוד יציאה שאינו 0), כך ששום דבר לא מדווח על הצלחה בטעות.
</details>

פותחים **סשן חדש**, והפלאגין פעיל.

**דרישות:** Node 18 ומעלה, שזמין כפקודה `node` (בודקים עם `node --version`). המתקין העצמאי של Claude Code (ה-native installer) לא מתקין Node, אז ייתכן שתצטרכו להתקין אותו בעצמכם מ-[nodejs.org](https://nodejs.org). בלעדיו שום דבר בפלאגין לא רץ, גם לא `show-doctor`. אין תלויות נוספות.

**נבדק על:** Windows 11, דרך Claude Code עצמו מקצה לקצה, עם חלונות אמיתיים ([דוח השחרור](RELEASE-REPORT.html), או [לצפייה בדוח כדף מעוצב](https://htmlpreview.github.io/?https://github.com/ofeklevy11/show-local/blob/main/RELEASE-REPORT.html)). **macOS ו-Linux בגרסת בטא.** הקוד שלהם מכוסה בבדיקות יחידה, ובכל שינוי התרחישים הבסיסיים רצים על מכונות ה-macOS וה-Ubuntu של GitHub: ב-macOS עם הפקודה `open` האמיתית ו-Finder (דף HTML, קובץ PDF, תיקייה שהקובץ הראשי בה מסומן, וגם סקריפט `.command`, אפליקציית `.app`, alias של Finder וקישור בשם `.pdf`, שכולם חייבים להיות מוצגים בתיקייה ולא לרוץ, וליד כל אחד בדיקת ביקורת שמראה שאותו קובץ כן רץ כשפותחים אותו ישירות); ב-Ubuntu, מה שמגיע ל-`xdg-open`. עוד לא השתמשו בהם ביום-יום על Mac או על מחשב Linux, אז נשמח לדיווחים.

## שימוש

אומרים את זה במילים שלכם:

- "תציג לי את הדוח"
- "תפתח לי בדפדפן את האתר"
- "תפתח את התיקייה עם הקבצים"
- "תראה לי את הסרטון"
- "show me", "open it in my browser", "open the folder"

או מקלידים את הפקודה: `/show-local:show <file, folder or URL>`.

בכל תשובה מופיעים הנתיב המלא או הכתובת המלאה כקישור לחיץ, כך שתמיד אפשר למצוא את התוצאה שוב.

Claude גם פותח לבד, פעם אחת, כשהוא מסיים משהו שנועד לעיניים שלכם (דוח, דף, סרטון, תיקיית תוצרים). קבצי ביניים ודפי בדיקה הוא לא פותח.

<details><summary>רשות: פקודה קצרה <code>/show-local</code></summary>

Claude Code נותן לפקודות ולסקילים של פלאגין שמות בצורה `/<plugin>:<name>`, ולכן הפלאגין עצמו מספק את `/show-local:show` ולא יכול לרשום פקודה קצרה `/show-local`. אם אתם רוצים להקליד רק `/show-local`, הוסיפו פקודה אישית משלכם. זה לא חובה, והיא רק מעבירה את הבקשה לסקיל `show` של הפלאגין. שמרו את הקובץ `~/.claude/commands/show-local.md` (ב-Windows: `%USERPROFILE%\.claude\commands\show-local.md`) בדיוק עם התוכן הזה:

```markdown
---
description: Open a file, folder or URL on this computer with show-local, and verify that it opened
argument-hint: <file, folder or URL>
---

Use the `show-local:show` skill (from the show-local plugin) to open this on the user's own computer and verify that it opened: $ARGUMENTS

If nothing was named, open the last deliverable made in this session that was meant for the user to look at.
```

מעכשיו Claude Code מציג `show-local` אישי ליד `show-local:show` של הפלאגין. הרשומה הזאת היא הקובץ הזה, ולא עותק שני של הפלאגין. כדי להסיר אותה, מוחקים את הקובץ.
</details>

## מה נפתח ואיפה

| מה יש להראות | מה קורה |
|---|---|
| כתובת http/https | נפתחת בדפדפן ברירת המחדל שלכם. בכתובת פשוטה נקראת קודם כותרת הדף, בשביל הבדיקה. כתובת שעלולה להיות קישור חד-פעמי אף פעם לא נטענת, וגם לא כתובת שמובילה למחשב שלכם או לרשת הביתית |
| קובץ HTML | נפתח באותו דפדפן, גם אם קבצי `.html` משויכים במחשב לתוכנה אחרת. ב-Windows, נתיב ארוך מדי בשביל `file:///` (מעל 256 תווים בערך) נפתח דרך השם הקצר שלו בתקן 8.3, כך שהקישור ממשיך לעבוד גם אחרי הסשן. רק כש-Windows לא נותן לו שם קצר, הוא מוגש משרת, ואז הקישור עובד רק כל עוד הסשן פתוח |
| HTML שצריך שרת (מודולים, `fetch`, JSON או קובץ נתונים מקומי אחר, בדף עצמו או בסקריפטים המקומיים שהוא טוען), או תיקייה עם `index.html` | שרת מקומי על `127.0.0.1` (הפורט הפנוי הראשון החל מ-4400), ואז בדפדפן |
| פרויקט עם `npm run dev` | שרת הפיתוח של הפרויקט עצמו (גם שרת https מקומי עם תעודה בחתימה עצמית עובד), ואז בדפדפן. הוא מופעל רק כשאתם רוצים שהאתר ירוץ |
| תיקיית תוצרים | מנהל הקבצים שלכם (סייר הקבצים, Finder או מנהל הקבצים של Linux), והקובץ הראשי מסומן |
| PDF או מסמך אחר (`.docx`, `.xlsx`, `.pptx`, `.epub`, `.xps`), תמונה, וידאו, אודיו, טקסט | בתוכנת ברירת המחדל שלו |
| תוכנה, סקריפט, קיצור דרך, קובץ מסוג לא מוכר או בלי סיומת, `.app` של macOS, מסמך שיכול להכיל מאקרו (`.doc`, `.xls`, `.ppt`, קובצי Office עם מאקרו, OpenDocument, `.rtf`) | מוצג מסומן במנהל הקבצים. הוא אף פעם לא מורץ |

**ב-Linux**, דפים וקבצי HTML נפתחים בפקודה של דפדפן ברירת המחדל עצמו: שורת ה-`Exec` בקובץ ה-`.desktop` שלו, זה ש-`xdg-settings` מחזיר. תיקיות נפתחות דרך ממשק ה-D-Bus של מנהל הקבצים, `org.freedesktop.FileManager1` (בקריאה עם `gdbus`), שיודע גם לסמן את הקובץ הראשי. `xdg-open` הוא הגיבוי של שניהם, והוא גם זה שפותח כל דבר אחר. כך קובץ HTML מגיע לדפדפן שלכם גם כש-`.html` משויך לתוכנה אחרת.

## איך יודעים שזה נפתח

Claude לא כותב "פתחתי" לפני שיש הוכחה:

- **Windows:** כותרות החלונות הפתוחים. למשל, חלון כרום עם כותרת הדף הופיע או השתנה אחרי הפתיחה. חלון אחר שרק שינה בינתיים את הכותרת שלו לא נחשב. תיקייה נבדקת דרך רשימת חלונות הסייר, כולל איזה קובץ מסומן: כשהתיקייה נפתחה אבל הקובץ הראשי לא מסומן בה, התשובה אומרת את זה.
- **דף שמוגש מהשרת הסטטי של show-local:** גם שורת `GET` ביומן השרת, מהרגע שהדפדפן ביקש את הדף.
- **שרת פיתוח של פרויקט:** רק התשובה של השרת ב-HTTP וכותרת החלון. שרת פיתוח שומר את מה שהוא רושם בפלט של עצמו, ו-show-local לא יכול לקרוא אותו, ולכן אין בשבילו שורה ביומן השרת.
- **macOS:** דרך AppleScript. בפעם הראשונה macOS עשוי לבקש הרשאת Automation לדפדפן ול-Finder.
- **Linux:** דרך `wmctrl` או `xdotool`, אם הם מותקנים. ב-Wayland נטו אי אפשר לקרוא כותרות חלונות.

הבדיקה מחכה לחלון עד 5 שניות. במחשב איטי אפשר להגדיר את משתנה הסביבה `SHOW_LOCAL_TIMEOUT_MS` (במילישניות), והיא תחכה יותר. ערך מעל 5000 גם מאריך באותה מידה את מגבלת הזמן של הפתיחה כולה, כך שכל ההמתנה מנוצלת. עם `0` לא מחפשים חלון בכלל: רק יומן השרת הסטטי של show-local עדיין יכול להוכיח שהדף נפתח, ואחרת התשובה אומרת שאי אפשר לאשר את זה.

"פתחתי" נאמר רק כשיש הוכחה אמיתית. כשהבדיקה רצה והחלון לא הופיע, התשובה אומרת את זה במפורש: "ניסיתי לפתוח ולא הצלחתי לאמת", עם הסיבה. כשאין שום דרך לבדוק, התשובה אומרת "ניסיתי לפתוח, אבל אין לי דרך לאשר שזה נפתח", עם הסיבה: למשל, חלון עם אותה כותרת כבר היה פתוח קודם, ולכן אי אפשר להבחין בחלון חדש. אף אחת מהתשובות האלה לא מנחשת: בלי "כנראה" ובלי הערכת סיכויים. במערכות מסוימות זו התשובה הרגילה, כי המערכת לא נותנת שום דרך לבדוק:

- **macOS:** קובץ שנפתח בתוכנה שלו (PDF, וידאו, תמונה), וכל דבר כש-AppleScript לא מורשה או כשמוגדר `SHOW_LOCAL_NO_OSASCRIPT=1`.
- **Linux:** כל דבר כשלא מותקן `wmctrl` וגם לא `xdotool`, וב-Wayland כל מה שלא מוגש מהשרת הסטטי של show-local (גם דף של שרת פיתוח).

דף מרוחק אף פעם לא נטען לפני שהוא נפתח אם הכתובת שלו עלולה להיות קישור חד-פעמי (כניסה לחשבון, איפוס סיסמה, הזמנה): כתובת עם שם משתמש או סיסמה, עם פרמטרים (`?…`) או עם עוגן (`#…`), או עם קטע נתיב ארוך או כזה שנראה כמו טוקן. טעינה מראש הייתה מנצלת קישור כזה. אז הכותרת שלו לא ידועה, ולכן בכל מערכת התשובה אומרת שאי אפשר לאשר שהוא נפתח. כתובת פשוטה, כמו `https://example.com/docs`, נטענת פעם אחת לפני הפתיחה, רק כדי לקרוא את הכותרת שלה בשביל הבדיקה. הבקשה הזאת יוצאת מ-show-local ולא מהדפדפן שלכם, ולכן היא לא נושאת את העוגיות או החשבונות המחוברים שלכם. אם היא לא מחזירה כותרת (שגיאה, קובץ במקום דף, הפניה לכתובת שעלולה להיות קישור חד-פעמי), התשובה אומרת שאי אפשר לאשר שהדף נפתח. כך גם דף מקומי, למשל של שרת פיתוח, שמפנה לכתובת שעלולה להיות קישור חד-פעמי (דף כניסה של שירות התחברות חיצוני): הדף נפתח, הכתובת הזאת לא נטענת, והתשובה אומרת שאי אפשר לאשר שהוא נפתח.

הבקשות האלה אף פעם לא מגיעות למחשב שלכם או לרשת הביתית בגלל מה שאתר מרוחק אמר. הבדיקה נעשית על הכתובת ששם הדומיין מתורגם אליה בפועל, ברגע החיבור, כך שכתובת מרוחקת, או הפניה ממנה, שמובילה לכתובת loopback, פרטית, link-local או לשירות המטא-דאטה של ענן (`127.0.0.1` תחת כל שם, `[::ffff:127.0.0.1]`, `192.168.x.x`, `10.x.x.x`, `169.254.169.254`) לא נטענת. הדף עדיין נפתח, והתשובה אומרת שאי אפשר לאשר שהוא נפתח. כותרת שנקראת מדף או מחלון מגיעה ל-Claude חתוכה ל-120 תווים, בלי תווי בקרה ובלי תווים בלתי נראים, והסקילים אומרים ל-Claude שזה טקסט מהדף ולא הוראות.

**מגבלה ידועה:** דף שמרענן את עצמו (טעינה מחדש אוטומטית, תגית refresh, בדיקות חוזרות מול השרת) וכבר פתוח בלשונית יכול לרשום `GET` משלו ביומן השרת. אז ההוכחה מיומן השרת עלולה להגיע מהלשונית הישנה ולא מזו שנפתחה עכשיו.

## אפליקציית הדסקטופ מול הטרמינל

השרת המקומי חי כל עוד הסשן פתוח:

| | אפליקציית הדסקטופ | טרמינל | הרצה בלי ממשק |
|---|---|---|---|
| הפעלת השרת | רשומה ב-`.claude/launch.json` של הפרויקט (הפלאגין ממזג אותה ולא נוגע בשאר), ואז `preview_start`. הרשומה מריצה `node`, אף פעם לא `cmd.exe` או `npm.cmd` | משימת רקע של Claude (`run_in_background`) | שום דבר ברקע: `oneshot`, פקודה אחת בחזית, מגישה את הדף, פותחת ומאמתת אותו, ממשיכה להגיש עוד 3 שניות ואז עוצרת את השרת |
| חלון התצוגה של Claude | נסגר מיד אחרי שהדף עלה אצלכם. השרת ממשיך לרוץ | אין | אין |

הרצה בלי ממשק היא הרצה שאף אחד לא יכול לענות לה אחרי התשובה האחרונה: `claude -p`, סקריפט, CI, תוכנה שבנויה על ה-SDK, סוכן-משנה (subagent) או שלב ב-workflow. סשן כזה לא יכול להסתיים כשרץ שרת, ולכן Claude מעביר שם `--headless` (סוכן-משנה ושלב ב-workflow יורשים את הסביבה של אפליקציית הדסקטופ, אז הדגל הוא מה שמודיע ל-show-local), והתשובה שלו אומרת שהוא עצר את השרת, אבל רק אחרי ש-show-local וידא שהפורט התפנה; אחרת התשובה מציינת את הפורט. הדף נשאר פתוח, אבל כדי לרענן אותו צריך שוב את השרת.

שרת סטטי מקבל את הפורט הפנוי הראשון החל מ-4400, ותיקייה שומרת על הפורט שלה כל עוד השרת שלה רץ או שהרשומה שלה נמצאת ב-`.claude/launch.json`.

שני סוגי השרתים עוקבים אחרי התהליך שהפעיל אותם: `node show.mjs serve` ו-`node show.mjs dev-run` בודקים בערך פעם בשנייה שהוא עדיין חי, ויוצאים כשהוא נעלם, כך שסשן שנסגר או נהרג לא משאיר אחריו שרת. `dev-run` הוא הדרך שבה show-local מריץ שרת פיתוח של פרויקט. הוא מפעיל `npm`, `pnpm`, `yarn` או `bun run dev` מתוך תיקיית הפרויקט, כך שהנתיב אף פעם לא מופיע בשורת פקודה (גם שם תיקייה עם `&` או `%` בטוח), רושם את השרת בשביל `servers`, ועוצר את כל עץ התהליכים של כלי הפיתוח (npm ו-Vite או Next שהוא מפעיל) כשהוא נעצר.

Claude עוצר את השרתים שהוא הפעיל כשאתם אומרים שסיימתם איתם. `node show.mjs servers` מציג את השרתים ש-show-local מכיר (השרתים הסטטיים שלו, ושרתי פיתוח שהוא הפעיל או פתח עליהם דף), ו-`node show.mjs stop <port>` עוצר אחד מהם.

**מגבלה ידועה:** שרת הפיתוח הוא הכלי של הפרויקט עצמו, ולא פעם השרת האמיתי רץ בתהליך-בן (npm מפעיל את Vite או את Next). show-local עוצר את כל העץ הזה כש-`dev-run` נעצר, כשהוא נהרג, וכשהסשן שהפעיל אותו נגמר. רק תהליך באמצע השרשרת שנהרג בכוח לבדו (`kill -9`, או סיום של התהליך הזה לבד במנהל המשימות) יכול להשאיר תהליך-בן שממשיך לרוץ ומחזיק את הפורט. תהליך ש-show-local כבר לא עוקב אחריו, אתם סוגרים בעצמכם (במנהל המשימות, ב-Activity Monitor או עם `kill`).

## שלושת הסקילים

| סקיל | פקודה | מתי |
|---|---|---|
| `show` | `/show-local:show` | לפתוח משהו ולהוכיח שנפתח. זה העיקרי |
| `show-serve` | `/show-local:show-serve` | להריץ אתר או פרויקט לוקאלית, לראות אילו שרתים רצים ולעצור אותם |
| `show-doctor` | `/show-local:show-doctor` | כשמשהו נפתח בתוכנה הלא נכונה או לא נפתח בכלל |

הכל רץ דרך סקריפט אחד בלי תלויות, `scripts/show.mjs`, שאפשר להריץ גם ידנית:

```bash
node show.mjs <path|url>                            # לפתוח ולאמת
node show.mjs plan <path|url> [--desktop|--headless] # מה יקרה; לא פותח כלום, אבל עם --desktop מוסיף או מעדכן את הרשומה ב-launch.json
node show.mjs oneshot <path|url>                    # בלי ממשק: להגיש, לפתוח, לאמת ואז לעצור את השרת
node show.mjs serve <folder>                        # שרת סטטי על 127.0.0.1
node show.mjs dev-run <project> --port <port>       # שרת הפיתוח של הפרויקט, נעצר עם כל עץ התהליכים שלו
node show.mjs servers                               # שרתים שרצים (סטטיים ופיתוח)
node show.mjs stop <port|all>                       # עצירה
node show.mjs doctor                                # בדיקת סביבה
```

## אבטחה

- השרת הסטטי של show-local מאזין רק ל-`127.0.0.1`, כך ששום מכשיר אחר ברשת לא רואה אותו. שרת פיתוח של פרויקט מאזין איפה שהפרויקט מגדיר לו (למשל `vite --host` פותח אותו לרשת): show-local לא כופה עליו `127.0.0.1`.
- השרת מגיש רק את התיקייה שנבחרה. backslash נחשב למפריד נתיב, כמו `/`. אחרי זה נחסמים `..` (גם בקידוד, כמו `%2e%2e`), אותיות כונן, alternate data streams ו-symlink שיוצא מהתיקייה, וגם קבצים ותיקיות שמתחילים בנקודה, כמו `.env` ו-`.git`, גם דרך השם הקצר שלהם ב-Windows (`ENV~1`).
- אין רשימת קבצים של תיקייה (directory listing).
- כותרת `Host` חייבת להיות המחשב עצמו, מה שחוסם התקפת DNS rebinding.
- הוא אף פעם לא מריץ את מה שביקשו להציג: רק סוגי קבצים מוכרים לצפייה נפתחים בתוכנה שלהם, וכל השאר מוצג בתיקייה שלו, כולל מסמכים שיכולים להכיל מאקרו (`.doc`, `.xls`, `.ppt`, `.rtf`, OpenDocument, קובצי Office עם מאקרו), קישור או alias של Finder שמובילים למשהו אחר, וחבילה של macOS. `--select` חייב להיות קובץ בתוך התיקייה.
- הבקשות שלו עצמו (כותרת של דף מרוחק, בדיקת המוכנות של דף מקומי) אף פעם לא מגיעות למחשב שלכם או לרשת הביתית בגלל מה שאתר מרוחק אמר: הכתובת ששם הדומיין מתורגם אליה נבדקת ברגע החיבור.
- תוכנות Windows שהוא מפעיל (PowerShell, `reg`, `netstat`, סייר הקבצים, `cmd.exe`, `taskkill`) רצות בנתיב המלא שלהן בתיקיית Windows, ותוכנות macOS בנתיב המערכת הקבוע שלהן, כך שקובץ באותו שם בתיקיית הפרויקט אף פעם לא ירוץ במקומן.
- כותרות של דפים וחלונות מגיעות ל-Claude חתוכות ל-120 תווים, בלי תווי בקרה ובלי תווים בלתי נראים, והסקילים אומרים ל-Claude שהן מידע ולא הוראות.
- כשפורט תפוס על ידי תהליך שאי אפשר לקשר לפרויקט, מדווחים רק ה-pid והשם של התהליך, ואף פעם לא שורת הפקודה שלו, שעלולה להכיל סודות.
- תוכנות ש-show-local מפעיל בעצמו מקבלות נתיבים וכתובות כארגומנטים נפרדים או כמשתני סביבה, אף פעם לא דרך shell. שורת הפקודה הקבועה היחידה היא של `dev-run` ב-Windows, שבו `npm`, `pnpm` ו-`yarn` הם סקריפטים מסוג `.cmd` שרק `cmd.exe` מריץ: הוא מריץ שם `<runner> run dev` כשתיקיית הפרויקט היא תיקיית העבודה, כך ששום נתיב לא נכנס לשורה. פקודות ההמשך שהוא מדפיס בשביל Claude (`next.start`, `next.then`, `next.oneshot`) הן מחרוזות shell לכלי ה-Bash של Claude, וכל נתיב בהן עטוף במירכאות בודדות בסגנון POSIX. ב-PowerShell צריך לצטט אותן מחדש: מירכאות בודדות, וכל גרש שבתוך הנתיב מוכפל.
- הפלאגין לא משנה אף הגדרה: לא דפדפן ברירת מחדל, לא שיוך קבצים, לא הגדרות דפדפן. הוא רק פותח.

הוק יודע **מתי** משהו קרה, למשל שנכתב קובץ או שנגמר תור. הוא לא יודע **מה** צריך להראות לכם: דף בדיקה או התוצר הסופי. הוק על כתיבת קבצים גם לא רואה קבצים שסקריפטים יוצרים (ffmpeg, build), והוק על מילים נדלק גם על "תציג תכנית". סקיל יודע מה בנינו. את העקביות של הוק לוקחים מהסקריפט: כל החלק המכני רץ בפקודה אחת, זהה בכל פעם.

## הסרה

אם `node show.mjs servers` עדיין מציג שרת, עצרו אותו קודם עם `node show.mjs stop all`, כל עוד הפלאגין מותקן. אחר כך:

```
/plugin uninstall show-local@show-local
/plugin marketplace remove show-local
```

ההסרה משאירה את תיקיית המצב של show-local: רישום השרתים, יומני הגישה, וב-Windows גם רכיב החלונות המהודר (`ShowLocalWin-*.dll`). מוחקים אותה בעצמכם. ב-Windows (ב-PowerShell):

```powershell
Remove-Item -Recurse -Force -ErrorAction SilentlyContinue "$env:TEMP\show-local", "$env:USERPROFILE\.cache\show-local"
```

ב-macOS וב-Linux:

```bash
rm -rf "${TMPDIR:-/tmp}/show-local-$(id -u)" ~/.cache/show-local
[ -n "$XDG_RUNTIME_DIR" ] && rm -rf "$XDG_RUNTIME_DIR/show-local-$(id -u)"
```

כלומר `%TEMP%\show-local` ב-Windows, `$TMPDIR/show-local-<uid>` ב-macOS, וב-Linux `$XDG_RUNTIME_DIR/show-local-<uid>` כשהמשתנה הזה מוגדר, ואחרת `show-local-<uid>` בתיקייה הזמנית. `~/.cache/show-local` הוא הגיבוי כשאי אפשר להשתמש בתיקייה הרגילה. תיקייה בתיקייה הזמנית ששמה `show-local-` ואחריו תווים אקראיים היא עותק חירום של אותו מצב, ואפשר למחוק גם אותה.

אם הרצתם שרת באפליקציית הדסקטופ, בפרויקט נשארות רשומות `show-…` (אחת לכל תיקייה שהוגשה או פרויקט פיתוח) בקובץ `.claude/launch.json`. אפשר למחוק אותן, והשאר לא נפגע.

אם הוספתם את הפקודה הקצרה `/show-local`, מחקו גם את `~/.claude/commands/show-local.md`.
